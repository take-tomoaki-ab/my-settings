## 手順 0: 申し送りの読み込み（省略禁止）

まず次を実行して、これまでの経緯と決定事項を読んでください。

```bash
cat <MEMORY_DIR>/plan.md
ls -1 <MEMORY_DIR>/*_result.md
cat <MEMORY_DIR>/<直前タスクの id>_result.md
```

**ToRide が割り当てた作業ディレクトリでそのまま作業してください。**
自分で `git worktree add` しないでください。

## 止まってよい条件

- **判断に迷ったら、勝手に決めずに報告してください。**
- **差分に確信が持てない場合は、push せずに報告してください。急がなくていいです。差分を壊すよりずっとマシです。**

## このリポジトリで実際に事故った注意（毎回コピーする）

<「一般論として危ない」ものは書かない。このリポジトリで実際に起きたものだけを書く>

- **`<フォーマッタのコマンド>` を実行しないこと** — リポジトリ全体が書き換わる。別タスクが実際に踏んだ
- **`declare -A` を使わないこと** — macOS の bash 3.2 は連想配列に非対応。レビュー返信 9 件が全部 1 スレッドに誤投稿された
- **PR 本文の既存の画像・添付を削除しないこと** — ユーザーが貼ったスクリーンショットを消した事故がある
- **PR 本文の更新は `gh api -F body=@pr.md`** — `gh pr edit --body-file` は黙って失敗する
- **レビュアーに読ませたい情報を HTML コメントに書かないこと** — 見えない

## 完了時（省略禁止）

1. `<MEMORY_DIR>/<このタスクの id>_result.md` を書いてください。
   **次のタスクの担当は、このファイルだけを読んで作業を始めます。そのつもりの粒度で書いてください。**
   **後続が直接使うエクスポート（コンポーネント名 / props / 関数シグネチャ / import パス）を必ず明示してください。**
2. `<MEMORY_DIR>/<このタスクの id>_DONE` を空ファイルで作ってください（通知が失われた場合の保険）。
3. **ToRide のタスクを自分で done にしないでください。** 完了判定はオーケストレーターがします。
4. 完了報告は、**私から届く `<cross-session-message from="...">` の `from` 属性をそのまま `to` に指定して**返信してください。
   **宛先を推測しないでください。私からのメッセージが届くまで待ってください。**
