# html スキル

## 概要

直近の会話でやり取りした内容を、**あとから読み返せる 1 枚の HTML ファイル**として書き出し、Chrome で開くスキルです。

会話ログの逐語コピーではありません。話題の結論・経緯・根拠を、初見の人間が読んで理解できる読み物に再構成します。

## トリガー条件

- ユーザーが `/html` を実行したとき
- 「今の話を HTML にまとめて」「さっきの調査を html で出して」などと言われたとき

## 引数

```text
/html [まとめる対象の指定] [--out <出力先ディレクトリ>]
```

- 引数なし: 直近の話題（後述）を対象にする
- 対象の指定あり: その指定を優先する（例: `/html Datadog のエラー調査だけ`）
- `--out <dir>`: 出力先を上書きする。指定がなければ既定値を使う

## 出力先

1. `--out` の指定があればそのディレクトリ
2. ユーザーが会話中に明示した出力先があればそれ
3. どちらもなければ **`~/Desktop/codes/html-output`**

出力先には手順 3 で必ず `mkdir -p` を実行します（既にあってもそのまま実行して構いません）。既存ファイルは**上書きしません**。毎回新しいファイルを追加していきます。

### ファイル名

```text
<YYYYMMDD-HHmm>-<内容を表す英小文字ケバブケース>.html
```

例: `20260810-1830-series-tab-log-spec.html`

日時は推測で書かず、必ず次のコマンドを **1 回だけ** 実行して取得します。

```bash
date "+%Y%m%d-%H%M %Y-%m-%d %H:%M"
# => 20260810-1830 2026-08-10 18:30
```

前半（`20260810-1830`）をファイル名に、後半（`2026-08-10 18:30`）を HTML の meta 行に使います。`date` を 2 回実行しないでください。

同名判定は **ファイル名全体の一致** で行います。日時部分が違えばスラッグが同じでも別ファイル扱いとし、連番は付けません。ファイル名全体が完全に一致する場合のみ、**既存ファイルには触れず、これから書く側**のファイル名末尾に `-2`, `-3` を付けます。

## 「直近の話題」の決め方

対象は、**現在の会話で直前に扱っていた一続きの話題**です。

- 会話全体が 1 つの話題なら、その全体
- 途中で話題が切り替わっている場合は、**最後の切り替え以降**を対象にする
- 判断に迷うほど話題が混在している場合のみ、どの範囲をまとめるかユーザーに 1 度だけ確認する

雑談や失敗した試行錯誤は、結論に影響したものだけを残します。

## 手順

### 1. 内容を整理する

書き出す前に、以下を頭の中で確定させます。

- **タイトル**: 話題を一言で表す日本語
- **結論 / TL;DR**: 最大 3 項目。読者が最初に知るべきこと（テンプレートの 2 項目は例示であり上限ではない）
- **本文の章立て**: 背景 → 調査・検討したこと → 決定事項 → 根拠 → 残課題、が基本形。話題に合わせて増減させる
- **参照**: 触れたファイルパス、URL、チケット番号、コマンド
- **meta 行の補足**: 次の 2 段階で決める。
  - **リポジトリ名は常に書く**（作業ディレクトリ名から取る。例: `journey-web`）
  - **ブランチ名・チケット番号は、その話題に関係するときだけ書く**。無関係なブランチ名は読者を誤らせるので書かない

### 2. HTML を書く

`assets/template.html` をベースにします。手順は次で固定です。

1. `<このスキルの base directory>/assets/template.html` を Read する
2. `{{...}}` のプレースホルダを実内容に置き換える
3. 出力先のパスに Write する

`cp` でコピーしてから Edit する方式は取りません。テンプレートファイル自体は書き換えないでください。

テンプレートの記法は次のとおりです。

- `{{...}}` は **すべて置換対象** です。中身は何を書くかの説明であり、そのまま出力に残してはいけません
- `<!-- -->` のコメントは書き方の指示です。置換後は削除します
- `<style>` 内の CSS は、使っていないクラス（`.tag`、`blockquote` など）も **そのまま残します**。削らないでください
- 章の見出し文言は、内容の実態に合わせて変えて構いません（例: 調査していないなら「調べたこと / 検討したこと」→「検討したこと」）

守ること。

- **単一ファイルで完結させる**。CSS は `<style>` にインライン。外部 CDN・外部フォント・外部画像は使わない（オフラインでも開けること）
- `<html lang="ja">` と `<meta charset="utf-8">` を必ず入れる
- ライト / ダーク両対応（テンプレートの `prefers-color-scheme` をそのまま活かす）
- コードは `<pre><code>` に入れ、`<`・`&` をエスケープする
- ファイルパスやコマンドは `<code>` でマークアップする
- 表にすると読みやすい情報（比較、対応表、パラメータ一覧）は積極的に `<table>` にする
- 内容が薄いのに章だけ作らない。書くことがない章は削る

章の増減は次の規則に従います。テンプレートの章立ては雛形であり、固定ではありません。

- **削る**: その章に書く内容が会話から得られないなら、章ごと削除する。「参照」章も例外ではなく、参照すべきファイルパス・URL・チケット番号が 1 つも無ければ削る。ライブラリのバージョン番号やコマンド名は「参照」に当たらない（本文中に `<code>` で書けば足りる）
- **増やす**: 会話に該当する情報があり、かつ既存のどの章に入れても収まりが悪い場合に限り追加する。情報が無いのに章を増やさない
- **例外**: 「決定事項」章だけは削らない。結論が出ていない場合も章を残し、「未決」と書く。何も決まらなかったこと自体が読者に必要な情報だから

各章のタグ構造（`<p>` / `<ul>` / `<table>`）は内容に合わせて変えて構いません。雛形のタグに縛られる必要はありません。

未確認・未検証・未決の情報は、次の形で必ず可視化します。

- 断定形で書かない（「〜です」ではなく「〜と見られます（未検証）」）
- 該当箇所を `<mark>` で囲み、「未確認」「未検証」「未決」のいずれかの語を本文に含める。`<mark>` の範囲は **文単位** とする（語句だけを囲まない）
- 会話に出てこない推測は原則書かない。読者の理解に必要で書く場合も、必ず未検証として上記の形で示す
- 結論が出ていない論点は、「決定事項」章に「未決」と明記する。決まったかのように書かない

### 3. 書き出す

```bash
mkdir -p <出力先>
```

したうえで Write します。

### 4. Chrome で開く

```bash
open -a "Google Chrome" "<出力したファイルの絶対パス>"
```

Chrome が見つからずに失敗した場合のみ `open "<path>"` で既定ブラウザにフォールバックし、その旨をユーザーに伝えます。

### 5. 報告

出力した絶対パスと、まとめた話題の範囲を 1〜2 行で報告します。HTML の中身をそのままチャットに貼り直さないでください。

## やらないこと

- 会話ログの逐語ダンプ
- 未確認の情報を断定して書くこと（確認できていないことは「未確認」と明記する）
- 出力先ディレクトリ内の既存ファイルの削除・上書き
