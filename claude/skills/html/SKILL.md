# html スキル

## 概要

直近の会話でやり取りした内容を、**あとから読み返せる 1 枚の HTML ファイル**として書き出し、Chrome で開くスキルです。

会話ログの逐語コピーではありません。話題の結論・経緯・根拠を、初見の人間が読んで理解できる読み物に再構成します。

## トリガー条件

- ユーザーが `/html` を実行したとき
- 「今の話を HTML にまとめて」「さっきの調査を html で出して」などと言われたとき

## 引数

```text
/html [まとめる対象の指定] [--out <出力先ディレクトリ>]
```

- 引数なし: 直近の話題（後述）を対象にする
- 対象の指定あり: その指定を優先する（例: `/html Datadog のエラー調査だけ`）
- `--out <dir>`: 出力先を上書きする。指定がなければ既定値を使う

## 出力先

1. `--out` の指定があればそのディレクトリ
2. ユーザーが会話中に明示した出力先があればそれ
3. どちらもなければ **`~/Desktop/codes/html-output`**

ディレクトリが無ければ `mkdir -p` で作成します。既存ファイルは**上書きしません**。毎回新しいファイルを追加していきます。

### ファイル名

```text
<YYYYMMDD-HHmm>-<内容を表す英小文字ケバブケース>.html
```

例: `20260810-1830-series-tab-log-spec.html`

日時は必ず `date "+%Y%m%d-%H%M"` を実行して取得します。推測で書かないでください。
同名ファイルが既に存在する場合は末尾に `-2`, `-3` を付けて退避します。

## 「直近の話題」の決め方

対象は、**現在の会話で直前に扱っていた一続きの話題**です。

- 会話全体が 1 つの話題なら、その全体
- 途中で話題が切り替わっている場合は、**最後の切り替え以降**を対象にする
- 判断に迷うほど話題が混在している場合のみ、どの範囲をまとめるかユーザーに 1 度だけ確認する

雑談や失敗した試行錯誤は、結論に影響したものだけを残します。

## 手順

### 1. 内容を整理する

書き出す前に、以下を頭の中で確定させます。

- **タイトル**: 話題を一言で表す日本語
- **結論 / TL;DR**: 3 行以内。読者が最初に知るべきこと
- **本文の章立て**: 背景 → 調査・検討したこと → 決定事項 → 根拠 → 残課題、が基本形。話題に合わせて増減させる
- **参照**: 触れたファイルパス、URL、チケット番号、コマンド

### 2. HTML を書く

`assets/template.html` をベースにします。テンプレートを読み込み、プレースホルダを実内容に置き換えて Write してください。

守ること。

- **単一ファイルで完結させる**。CSS は `<style>` にインライン。外部 CDN・外部フォント・外部画像は使わない（オフラインでも開けること）
- `<html lang="ja">` と `<meta charset="utf-8">` を必ず入れる
- ライト / ダーク両対応（テンプレートの `prefers-color-scheme` をそのまま活かす）
- コードは `<pre><code>` に入れ、`<`・`&` をエスケープする
- ファイルパスやコマンドは `<code>` でマークアップする
- 表にすると読みやすい情報（比較、対応表、パラメータ一覧）は積極的に `<table>` にする
- 内容が薄いのに章だけ作らない。書くことがない章は削る

### 3. 書き出す

```bash
mkdir -p <出力先>
```

したうえで Write します。

### 4. Chrome で開く

```bash
open -a "Google Chrome" "<出力したファイルの絶対パス>"
```

Chrome が見つからずに失敗した場合のみ `open "<path>"` で既定ブラウザにフォールバックし、その旨をユーザーに伝えます。

### 5. 報告

出力した絶対パスと、まとめた話題の範囲を 1〜2 行で報告します。HTML の中身をそのままチャットに貼り直さないでください。

## やらないこと

- 会話ログの逐語ダンプ
- 未確認の情報を断定して書くこと（確認できていないことは「未確認」と明記する）
- 出力先ディレクトリ内の既存ファイルの削除・上書き
