# html スキル

## 概要

直近の会話でやり取りした内容を、**あとから読み返せる 1 枚の HTML ファイル**として書き出し、Chrome で開くスキルです。

会話ログの逐語コピーではありません。話題の結論・経緯・根拠を、初見の人間が読んで理解できる読み物に再構成します。

**Markdown を HTML タグに置き換えるだけの出力にはしません。** 仕組み・流れ・比較といった、文章から組み立て直さないと見えない情報は図にします。文章のままが速いものは文章で書きます。

## トリガー条件

- ユーザーが `/html` を実行したとき
- 「今の話を HTML にまとめて」「さっきの調査を html で出して」などと言われたとき

## 引数

```text
/html [まとめる対象の指定] [--out <出力先ディレクトリ>]
```

- 引数なし: 直近の話題（後述）を対象にする
- 対象の指定あり: その指定を優先する（例: `/html Datadog のエラー調査だけ`）
- `--out <dir>`: 出力先を上書きする。指定がなければ既定値を使う

## 出力先

1. `--out` の指定があればそのディレクトリ
2. ユーザーが会話中に明示した出力先があればそれ
3. どちらもなければ **`~/Desktop/codes/html-output`**

出力先には手順 3 で必ず `mkdir -p` を実行します（既にあってもそのまま実行して構いません）。既存ファイルは**上書きしません**。毎回新しいファイルを追加していきます。

### ファイル名

```text
<YYYYMMDD-HHmm>-<内容を表す英小文字ケバブケース>.html
```

例: `20260810-1830-series-tab-log-spec.html`

日時は推測で書かず、必ず次のコマンドを **1 回だけ** 実行して取得します。

```bash
date "+%Y%m%d-%H%M %Y-%m-%d %H:%M"
# => 20260810-1830 2026-08-10 18:30
```

前半（`20260810-1830`）をファイル名に、後半（`2026-08-10 18:30`）を HTML の meta 行に使います。`date` を 2 回実行しないでください。

同名判定は **ファイル名全体の一致** で行います。日時部分が違えばスラッグが同じでも別ファイル扱いとし、連番は付けません。ファイル名全体が完全に一致する場合のみ、**既存ファイルには触れず、これから書く側**のファイル名末尾に `-2`, `-3` を付けます。

## 「直近の話題」の決め方

対象は、**現在の会話で直前に扱っていた一続きの話題**です。

- 会話全体が 1 つの話題なら、その全体
- 途中で話題が切り替わっている場合は、**最後の切り替え以降**を対象にする
- 判断に迷うほど話題が混在している場合のみ、どの範囲をまとめるかユーザーに 1 度だけ確認する

雑談や失敗した試行錯誤は、結論に影響したものだけを残します。

## 手順

### 1. 内容を整理する

書き出す前に、以下を頭の中で確定させます。

- **タイトル**: 話題を一言で表す日本語
- **結論 / TL;DR**: 最大 3 項目。読者が最初に知るべきこと（テンプレートの 2 項目は例示であり上限ではない）
- **本文の章立て**: 背景 → 調査・検討したこと → 決定事項 → 根拠 → 残課題、が基本形。話題に合わせて増減させる
- **参照**: 触れたファイルパス、URL、チケット番号、コマンド
- **meta 行の補足**: 次の 2 段階で決める。
  - **リポジトリ名は常に書く**（作業ディレクトリ名から取る。例: `journey-web`）
  - **ブランチ名・チケット番号は、その話題に関係するときだけ書く**。無関係なブランチ名は読者を誤らせるので書かない
- **図にする箇所**: 後述の「図を入れる」の基準で 0〜2 個を先に決める。書き始めてから足すのではなく、章立てと同時に決める

### 2. HTML を書く

`assets/template.html` をベースにします。手順は次で固定です。

1. `<このスキルの base directory>/assets/template.html` を Read する
2. `{{...}}` のプレースホルダを実内容に置き換える
3. 出力先のパスに Write する

`cp` でコピーしてから Edit する方式は取りません。テンプレートファイル自体は書き換えないでください。

テンプレートの記法は次のとおりです。

- `{{...}}` は **すべて置換対象** です。中身は何を書くかの説明であり、そのまま出力に残してはいけません
- `<!-- -->` のコメントは書き方の指示です。置換後は削除します
- `<style>` 内の CSS は、使っていないクラス（`.tag`、`blockquote` など）も **そのまま残します**。削らないでください
- 章の見出し文言は、内容の実態に合わせて変えて構いません（例: 調査していないなら「調べたこと / 検討したこと」→「検討したこと」）

守ること。

- **単一ファイルで完結させる**。CSS は `<style>` にインライン。外部 CDN・外部フォント・外部画像は使わない（オフラインでも開けること）
- `<html lang="ja">` と `<meta charset="utf-8">` を必ず入れる
- ライト / ダーク両対応（テンプレートの `prefers-color-scheme` をそのまま活かす）
- コードは `<pre><code>` に入れ、`<`・`&` をエスケープする
- ファイルパスやコマンドは `<code>` でマークアップする
- 表にすると読みやすい情報（比較、対応表、パラメータ一覧）は積極的に `<table>` にする
- 内容が薄いのに章だけ作らない。書くことがない章は削る

章の増減は次の規則に従います。テンプレートの章立ては雛形であり、固定ではありません。

- **削る**: その章に書く内容が会話から得られないなら、章ごと削除する。「参照」章も例外ではなく、参照すべきファイルパス・URL・チケット番号が 1 つも無ければ削る。ライブラリのバージョン番号やコマンド名は「参照」に当たらない（本文中に `<code>` で書けば足りる）
- **増やす**: 会話に該当する情報があり、かつ既存のどの章に入れても収まりが悪い場合に限り追加する。情報が無いのに章を増やさない
- **例外**: 「決定事項」章だけは削らない。結論が出ていない場合も章を残し、「未決」と書く。何も決まらなかったこと自体が読者に必要な情報だから

各章のタグ構造（`<p>` / `<ul>` / `<table>`）は内容に合わせて変えて構いません。雛形のタグに縛られる必要はありません。

未確認・未検証・未決の情報は、次の形で必ず可視化します。

- 断定形で書かない（「〜です」ではなく「〜と見られます（未検証）」）
- 該当箇所を `<mark>` で囲み、「未確認」「未検証」「未決」のいずれかの語を本文に含める。`<mark>` の範囲は **文単位** とする（語句だけを囲まない）
- 会話に出てこない推測は原則書かない。読者の理解に必要で書く場合も、必ず未検証として上記の形で示す
- 結論が出ていない論点は、「決定事項」章に「未決」と明記する。決まったかのように書かない

#### 図を入れる

図は装飾ではありません。**冷えた読み手が、散文から自分で組み立て直さないと見えない仕組み**を見せるときにだけ描きます。1 文で言えるなら 1 文で書いてください。

図が必要になる典型は次です。1 つの HTML につき **0〜2 個** が目安で、無理に入れません。

| 状況 | 描くもの |
|---|---|
| データや制御がどこを通るか | 起点 → 経由 → 終点のフロー。増える / 消えるホップを強調する |
| 変更の前後 | before / after を並べ、**変わる 1 本の線**が分かるようにする |
| 選択肢の比較 | 案ごとに何が増減するかの差分。案を並べただけの箱は比較ではない |
| 状態が移り変わる | 状態遷移。遷移のきっかけを矢印ラベルに書く |
| 発生条件が絡む不具合 | 正常系と異常系の分岐点 |

**mermaid は使えません。** ローカルの `file://` で開く HTML では mermaid は描画されず、コードがそのまま表示されます。図は必ず **手書きの inline SVG** で描いてください。

inline SVG の作法は次のとおりです。

- **サイズは `viewBox` で決める**。`viewBox="0 0 W H"` を内容に合わせて選び、表示幅は CSS（テンプレートの `figure svg`）に任せる。横方向のフローは左→右、階層は上→下
- **色は `currentColor` を基本にする**。線・文字・矢印を `currentColor` にすればライト / ダーク両方で読める。**意味を持つ 1 要素だけ** `var(--accent)` を使い、それ以外に色を足さない
- **矢印には必ずラベルを付ける**。無印の矢印は「何か関係がある」しか伝えない。`書き込む`、`無効化`、`30 秒ごとに polling` と書く
- **矢印は `<marker>` か `<polygon>`** で描く。画像は使わない
- **文字は 11〜13px、短く**。説明文は図の中ではなく `<figcaption>` に書く
- **グリッドに揃える**。箱の `y` と高さ、矢印の `y` を共有し、間隔を均等にする。目分量のズレはノイズに見える
- **1 図 1 主張**。`<figure>` で包み、`<figcaption>` に「この図が示していること」を書く。`<svg>` には `role="img"` と同じ内容の `aria-label` を付ける
- **SVG の中に `<script>` / `<style>` / `<foreignObject>` を書かない**。長大な `path` データが必要になったら、それは図が複雑すぎるサイン。単純化する

雛形は次のとおりです。これをコピーして箱の数・位置・ラベルを内容に合わせて調整してください。

```html
<figure class="diagram">
 <div class="diagram__scroll">
  <svg viewBox="0 0 640 130" role="img" aria-label="{{図が示す主張を 1 文で}}">
    <defs>
      <marker id="arw" viewBox="0 0 10 10" refX="9" refY="5"
              markerWidth="7" markerHeight="7" orient="auto-start-reverse">
        <path d="M0,0 L10,5 L0,10 z" fill="currentColor" />
      </marker>
    </defs>

    <rect x="10" y="35" width="150" height="60" rx="8" fill="none" stroke="currentColor" />
    <text x="85" y="70" text-anchor="middle" font-size="13" fill="currentColor">{{起点}}</text>

    <rect x="245" y="35" width="150" height="60" rx="8" fill="none" stroke="var(--accent)" stroke-width="2" />
    <text x="320" y="70" text-anchor="middle" font-size="13" fill="var(--accent)">{{論点の中心}}</text>

    <rect x="480" y="35" width="150" height="60" rx="8" fill="none" stroke="currentColor" />
    <text x="555" y="70" text-anchor="middle" font-size="13" fill="currentColor">{{終点}}</text>

    <line x1="160" y1="65" x2="238" y2="65" stroke="currentColor" marker-end="url(#arw)" />
    <text x="199" y="54" text-anchor="middle" font-size="11" fill="currentColor">{{何が流れるか}}</text>

    <line x1="395" y1="65" x2="473" y2="65" stroke="currentColor" marker-end="url(#arw)" />
    <text x="434" y="54" text-anchor="middle" font-size="11" fill="currentColor">{{何が流れるか}}</text>
  </svg>
 </div>
  <figcaption>{{この図が示していること}}</figcaption>
</figure>
```

`viewBox` の幅は **640 を基準**にします（テンプレートの `figure svg { min-width: 640px }` と対応しており、ここを縮めると SP で図全体が縮小され、文字が 8px 台になって読めなくなります）。高さだけを内容に応じて増やしてください。`<svg>` は必ず `.diagram__scroll` で包みます。

`<marker>` は **色ごとに 1 つ用意します**。雛形の `arw` は `fill="currentColor"` なので、`var(--accent)` の線にそのまま使うと線だけ色付きで矢じりが地の色になります。accent の矢印を引くなら `fill="var(--accent)"` の `arwAcc` を別に定義してください。`id` は同じ図の中でも別の図との間でも**重複させない**でください。

##### 文字が溢れないようにする

**生成した SVG の描画結果を目で確認する手段はありません。** 座標計算だけで溢れを防ぐ必要があります。次の見積もりを使ってください。

- 日本語 1 文字 ≒ `font-size` と同じ px（13px なら 1 文字 13px）
- 英数字・記号 1 文字 ≒ `font-size × 0.6`（13px なら約 8px）

この見積もりで**ラベルの幅を計算してから**座標を決めます。

| 置き場所 | 使える幅 | ラベルの上限 |
|---|---|---|
| 箱の中（13px） | 箱幅 − 20 | 箱幅 150 なら日本語 10 文字まで |
| 矢印の上（11px） | 箱と箱の隙間 − 10 | 隙間 70 なら日本語 5 文字まで |

収まらないときの対処は、**優先順に** 次のとおりです。

1. **語を削る**（`cleanup なし` → `解除なし`、`null を参照` → `null 参照`）。矢印ラベルは 3〜6 文字を目安にする
2. **箱を広げて隙間を確保する**（箱幅を狭め、`x` を再配置して隙間を 70 以上にする）
3. `<tspan>` で 2 行に割る（`x` を親と同じ値にし、`dy="1.2em"` で送る）

`font-size` を 10 以下に下げるのは最後の手段です。読めなくなります。

##### 4 ステップ以上の連鎖を描く

横 1 行に 3 箱までしか置けません。4 つ以上なら 2 行に折り返します。座標は次で固定してください。

次の座標は実際に描画して重なりが無いことを確認済みです。そのまま使ってください。

- 箱は `x=10 / 245 / 480`、`width=150`、`height=54`（隙間 85）
- 1 行目 `y=26`、2 行目 `y=138`。`viewBox` は `0 0 640 210`
- 折り返しは `<polyline>` で「右端の箱の下 → 下へ（`y=112`）→ 左へ → 2 行目の左端の箱の上」と回す
- 折り返し線のラベルは `y=104` 付近に置く（上段の箱の下端 80 と水平線 112 の間）
- 折り返し線にもラベルを付ける。付けられないなら、それは連鎖ではなく別の図
- 折り返し線のラベルに使える幅は **水平部分の長さ − 20** です（箱間の隙間ではありません）

箱の中を `<tspan>` で 2 行にするときは、1 行目のベースラインを **箱の中心 − 8**（`y=26`・高さ 54 の箱なら `y=45`）に置き、2 行目を `dy="1.2em"` で送ります。`x` は親の `<text>` と同じ値を明示してください。

##### 図を 2 つ描くときの基準

2 つ目の図は、**1 つ目と登場する箱が 3 分の 1 以上重なるなら描きません**。同じ絵の描き直しになります。その場合は `.cards` による並置か、表に落としてください。

`var(--accent)` を使うのは **1 つの主張を構成する一組** までです。論点の中心の箱と、その箱に出入りする矢印・矢印ラベルまでは同じ色で構いません。それ以外の箱に色を足すと、どこが論点か分からなくなります。

#### 視覚要素を使う

図にするほどではない情報も、地の文に流し込まず、テンプレートに用意した部品で構造を見せます。

| 部品 | クラス | 使いどころ |
|---|---|---|
| コールアウト | `.callout` / `.callout--warn` | 決定事項、読み飛ばすと困る注意。章の冒頭に 1 つ |
| ステータスバッジ | `.badge` / `.badge--ok` / `.badge--todo` | 表の中で「確認済み / 未検証 / 未決」を一目で区別する |
| 比較カード | `.cards` > `.card` | 2〜3 案の並置、before / after の対比 |
| 番号付きステップ | `.steps` | 手順・時系列。順序に意味があるときだけ |
| 数値の強調 | `.stat` | 件数・時間・割合など、読者が覚えて帰る数字 |

使い方の原則です。

- **1 章に装飾を 2 つまで**。全部が強調されているページは、何も強調されていないのと同じ。数えるのは**章の地の文に置いた部品**だけです。`<table>` と `<figure>` は構造なので数えず、表のセルの中に入れた `.badge` も表の一部として数えません
- **比較は必ず横に並べる**。上下に離すと読者が差分を取れない
- **確からしさに幅がある表には状態列を作る**。`<td><span class="badge badge--todo">未検証</span></td>` のように、行ごとの確度が目で分かるようにする。全行が確定事実の表には要りません
- `.stat` は**独立した短い段落**に置きます。本文の行中に置くと行間が崩れます
- 意味の無い色を足さない。色を使うのは `--accent`（論点の中心）と `--hot`（未検証・危険）の 2 つだけ

### 3. 書き出す

```bash
mkdir -p <出力先>
```

したうえで Write します。

### 4. Chrome で開く

```bash
open -a "Google Chrome" "<出力したファイルの絶対パス>"
```

Chrome が見つからずに失敗した場合のみ `open "<path>"` で既定ブラウザにフォールバックし、その旨をユーザーに伝えます。

### 5. 報告

出力した絶対パスと、まとめた話題の範囲を 1〜2 行で報告します。HTML の中身をそのままチャットに貼り直さないでください。

## やらないこと

- 会話ログの逐語ダンプ
- 未確認の情報を断定して書くこと（確認できていないことは「未確認」と明記する）
- 出力先ディレクトリ内の既存ファイルの削除・上書き
